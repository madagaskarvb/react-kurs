# Как сдавать работы

Пошаговая инструкция с картинками для всех случаев — на сайте курса:
[работа с репозиторием](https://algorthimization-course-vvodnoe.vercel.app/angular-react/repozitoriy/index.html). Здесь — правила, которые проверяет преподаватель.

## Куда класть работу

| Работа | Папка | Пример пути |
|---|---|---|
| доска заявок из глав | `zayavki/` | `zayavki/src/App.tsx` |
| автоматизация | `avtomatizaciya/` | `avtomatizaciya/compose.yaml` |
| проект модуля | `projects/pN-<вариант>/` | `projects/p1-obshchezhitie/src/App.tsx` |
| процессы n8n проекта 2 | `projects/p2-<вариант>/n8n/` | `projects/p2-obshchezhitie/n8n/ii-dispetcher.json` |
| ссылки и журнал проекта 3 | `projects/p3-monitoring/` | `projects/p3-monitoring/README.md` |

Папки `zayavki` и `avtomatizaciya` создаются по шагам глав 1.1 и «Автоматизация» модуля 1 прямо
в этом репозитории: он и есть папка курса `react-kurs`.

## Имена папок и файлов

| Правило | Правильно | Неправильно |
|---|---|---|
| латинские буквы, цифры, `-` и `_` | `p1-obshchezhitie` | `п1-общежитие` |
| без пробелов | `p2-studsovet` | `p2 studsovet` |
| папка проекта — маленькие буквы, слова через `-` | `p1-obshchezhitie` | `P1_Obshchezhitie` |
| компонент React — с большой буквы, как в главах | `RequestCard.tsx` | `requestCard.tsx` |
| остальные файлы кода — с маленькой | `api.ts`, `useRequests.ts` | `Api.ts` |

## Сообщение коммита

Первое слово — папка или проект, затем глава или что сделано:

| Работа | Сообщение |
|---|---|
| доска по главе 1.5 | `zayavki 1.5: список, ключи, фильтр` |
| исправление | `zayavki 2.3: ошибка загрузки при остановленном PocketBase` |
| проект | `p1 obshchezhitie: форма и категории` |
| автоматизация | `avtomatizaciya: процесс «ИИ-диспетчер»` |

Сообщения `update`, `fix`, `файлы`, `123` не принимаются: по ним нельзя понять, что изменилось.

## Перед отправкой

1. В папке работы выполнены `npm run build` и `npm run lint` — без ошибок и предупреждений.
2. Токен бота хранится только в `avtomatizaciya/.env`, и этот файл не попадает в коммит (он в `.gitignore`).
3. В папке проекта есть `README.md` и `ai-log.md`.
4. Работа ушла на GitHub: на странице репозитория виден ваш коммит.
5. На вкладке **Actions** проверка «Проверка работ» с зелёной галочкой.

Все работы загружаются в ветку `main`. Отдельные ветки и Pull Request для заданий не создаются.

## Что проверяет GitHub Actions

После каждой отправки запускается проверка «Проверка работ»
([`.github/workflows/check-work.yml`](../.github/workflows/check-work.yml)):

| Проверка | Красный крестик, если |
|---|---|
| секреты | в коммите есть файл `.env` или строка, похожая на токен бота Telegram |
| сборка | в папке с `package.json` не проходит `npm ci`, `npm run build` или `npm run lint` |

Отчёт открывается щелчком по запуску на вкладке **Actions**: в нём таблица папок и строка с ошибкой.
Если токен попал в коммит, его нужно сразу отозвать у @BotFather (`/revoke`) и выпустить новый:
удаление файла не стирает токен из истории.
